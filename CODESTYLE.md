# CODESTYLE

Правила кода `cloudru-dbaas`. Планка — `CONSTRAINTS.md`.
Источники: [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments), [clig.dev](https://clig.dev/),
образцы — [hcloud](https://github.com/hetznercloud/cli) (раскладка), [nelm](https://github.com/werf/nelm) (дисциплина), [gh](https://github.com/cli/cli) (CLI).
Что ловит линтер — здесь не повторяется.

## Устройство

1. **Интерфейс объявляет потребитель** и только из нужных ему методов; производитель (`cloud`, `auth`)
   отдаёт конкретные типы. «Вход — интерфейсы, выход — структуры».
2. **Зависимости — только вниз:** `internal/cmd` → `state` → `cloud`, `transport`, `auth`, `config`, `output`; `cloud` → `gen`.
   Команды не знают про HTTP, JSON и env — границы записаны в `.golangci.yaml` (`depguard`/`forbidigo`).
3. **Команда:** файл на глагол (`create.go` + `create_test.go`); флаги → `<Verb>Options` → вызов → вывод;
   конструктор `NewCmdX(f, runF)` — разбор флагов тестируется без сети.
4. **Без functional options:** `<Name>Options` последним аргументом (как nelm).
5. **Зависимости в `state` — ленивые** (функции, как `Factory` в gh): `version`, `help`, `completion` без ключа.

## Ошибки

6. Внизу — sentinel-ошибки и обёртка `%w`; текст пользователю — наверху, в `output`.
7. Код выхода — по виду сбоя: 0 успех, 1 ошибка, 2 отмена, 4 ключ или доступ, 8 операция ещё идёт.
8. Повторяются только идемпотентные запросы; создание — никогда.

## Ввод и вывод

9. Данные — в stdout, сообщения и прогресс — в stderr. Цвет — только в терминале и не при `NO_COLOR`.
10. Вопрос — только в терминале; вне терминала разрушающая команда требует `--yes`; `--no-input` выключает вопросы.
11. Ctrl-C во время `--wait` — сразу сообщение «операция продолжается в облаке, id …» и выход.

## Тесты

12. Юнит — `testing` + testify (`require` для предусловий, `assert` для проверок), таблицы, `t.Parallel()`.
13. Контекст в тестах — `t.Context()`, не `context.Background()` (линтер `usetesting`).
14. Моки — mockery по интерфейсам потребителя; HTTP-слой — `httptest` с заглушками ответов.
15. e2e — Ginkgo + Gomega в `tests/e2e/`, бинарник через `gexec`.
16. Тест называется по команде или модулю, не по прогону.
17. Правило API, узнанное вживую, — в тест: заглушка проверяет тело запроса тем же условием, что API.
