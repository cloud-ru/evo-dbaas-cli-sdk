# Fuzz-проверки разбора CLI и API

Изменение относится к гейтам качества и разбору ответов облака (пакеты cloud и base).
Меняет поведение: мусор после единственного JSON-документа списка отклоняется,
легитимные пробелы до и после документа принимаются.

Рост строк: проверка конца JSON страницы API устраняет молчаливое принятие мусора,
найденного fuzz-тестом. Ручные строки: 7931 → 7935 (+4), по tools/ratchet.

## Найденная ошибка и изменение golden

Минимальный ответ `{}0` сохранён в
`internal/cloud/testdata/fuzz/FuzzWalkOffsets/88ee4165ba782ed3`.
`budget.fetch` принимал первый объект и игнорировал остаток тела. Теперь после
документа требуется EOF, иначе возвращается ErrList. Завершающие JSON-пробелы
разрешены. Проверка `InputOffset() == len(raw)` вместо EOF недопустима: она
отвергает корректный документ с LF или CRLF/табуляцией/пробелом после него.
Panic не найден.

Golden `edge_список_с_мусором_после_json.golden` фиксирует для ответа Redis `{}0`:
exit 1, пустой stdout и
`error: list not assembled: trailing data in response clusters` в stderr.
Запросы: POST /iam/token и GET /redis/v1/clusters с прежними параметрами.
Регрессия этой строки сетки: ложный успешный пустой список из повреждённого
ответа API; юнит-свойство не фиксирует код выхода, stdout/stderr бинарника.

## Обёртки UUID: решено — только фигурные скобки

Fuzz показал: `parseUUID` принимал `a<uuid>b` и любую другую пару символов вокруг
36-символьного id — google/uuid.Parse для длины 38 обёртку не проверяет. Решение
владельца: чинить. Теперь из 38-символьных форм принимается только `{<uuid>}`,
остальные — `ErrNotUUID` (`TestParseUUIDRejectsForeignWrappers`, свойство FuzzParseUUID
без допуска для этого класса). Канонический, слитный и `urn:uuid:` вид — без изменений.

## Гейты и доказательства

Основной гейт seed-корпуса — обычный go test в task check с race.
`task fuzz` сверяет 13 обязательных имён с обнаруженными Fuzz-целями в четырёх
пакетах. Отсутствие любого имени — ошибка; дополнительные цели тоже запускаются.
Каждая цель запускается отдельно с `-fuzz=^FuzzXxx$ -fuzztime=5s -parallel=2`.
Короткий прогон вынесен в самостоятельный CI job и не удлиняет локальный task check.
При падении job настроена выгрузка `**/testdata/fuzz/**` через actions/upload-artifact,
закреплённый полным SHA релиза v4.6.2.

[Дословные красные и зелёные прогоны мутантов](fuzz-mutation-evidence.md) подтверждают:

- замена EOF сравнением смещения ломает таблицу допустимых пробелов;
- удаление FuzzOneOf ломает task fuzz, хотя другие цели пакета остаются;
- обрезание ведущего пробела UUID ломает левую границу;
- добавление `*~` в безопасный набор shellValue ломает seed-корпус;
- ParseInt с основанием 0 ломает десятичную грамматику seed-корпуса.

Итоговый локальный прогон: task fuzz — 13 PASS за 109.829 с;
task check BASE=main — линтер без замечаний, уязвимостей нет, генерация
воспроизводится (8 файлов), 2223 теста с race прошли, покрытие ручного кода 96.2%
