# Коды выхода и долгие операции — Redis

Код выхода: `0` — успех, `1` — ошибка API или ввода, в том числе операция в
облаке завершилась ошибкой (причина в stderr), `2` — отмена (Ctrl-C), `4` — ключ
или доступ, `8` — **ожидание оборвалось, а операция в облаке могла
продолжиться** (истёк `--timeout`, 5 сбоев опроса подряд или ответ без операции).

- На `8` не пересоздавай: в stderr — id операции и команда, которой её
  дождаться; добавь к ней тот же `--timeout`, что был у первого вызова.
- **Код `1` после `create` тоже не значит, что кластера нет**: запрос мог
  дойти, а упал опрос или чтение кластера. Перед повтором найди кластер по
  имени в `clusters list --json` (имя бери уникальное, с суффиксом).
- **Ожидание дольше лимита твоего шелла** (часто 10 минут) убьёт процесс без
  кода и без id операции. Тогда запускай `create` без `--wait`, запиши `id`
  операции из ответа и жди её в фоне:

```bash
cloudru-dbaas redis operations get <OP_ID> --wait --timeout 60m --json
cloudru-dbaas redis operations list <CLUSTER_ID> --json      # все операции кластера
```

  Процесс всё же убит — сначала ищи кластер по имени, не пересоздавай.
